## filepath.Glob 与 LoadHTMLGlob {#glob}

### 问题

Gin 中：

```go
r.LoadHTMLGlob("templates/**/*")
```

发现：

- 子目录模板能加载
- `templates` 根目录下的模板加载不到

### 原因

Gin 底层使用的是 Go 的 `filepath.Glob`。

`templates/**/*` 的含义是：

1. 进入 `templates`
2. 匹配任意一个子目录
3. 匹配子目录下的文件

❗ **不会匹配 templates 根目录下的文件**

这是一个非常经典的坑。

### 解决方案

改为：

```go
r.LoadHTMLGlob("templates/*")
```

或者：

```go
r.LoadHTMLGlob("templates/**/*.html")
```

或者分别加载：

```go
r.LoadHTMLGlob("templates/*")
r.LoadHTMLGlob("templates/**/*")
```

## .gitignore 不生效 {#gitignore}

### 现象

`.gitignore` 已写：

```
tmp/logs/app.log
```

但仍然被提交。

### 原因

`.gitignore` 只对 **未被跟踪的文件** 生效。

如果之前已经：

```bash
git add tmp/logs/app.log
git commit
```

那这个文件已经进入 Git 索引。

### 解决方案

```bash
git rm --cached tmp/logs/app.log
```

然后重新 commit。

## int64 ID 前端丢失精度 {#int64}

### 现象

后端返回：

```
262122264495919100
```

前端 JS 打印：

```
262122264495919104
```

导致：

- 详情页 404
- 有时能打开，有时打不开

------

### 原因

#### Go

`int64` 最大值：

```
2^63 - 1
```

#### JavaScript

JS 所有数字都是 IEEE 754 双精度浮点数。

安全整数最大值：

```
2^53 - 1
```

即：

```js
Number.MAX_SAFE_INTEGER
```

当雪花 ID 超过 16 位：

➡ JS 自动舍入
➡ 精度丢失
➡ ID 改变

------

### 解决方案

在 Go struct 中：

#### 修改前

```go
ID int64 `json:"id"`
```

#### 修改后

```go
ID int64 `json:"id,string"`
```

让 ID 以字符串形式传给前端。

## 切片 nil 与空切片区别 {#slice}

```go
articles := []model.ResponseArticle{}
```

与

```go
var articles []model.ResponseArticle
```

区别：

| 写法   | 值     | 是否为 nil |
| ------ | ------ | ---------- |
| 第一种 | 空切片 | 否         |
| 第二种 | nil    | 是         |

建议：

返回 JSON 时用第一种，避免前端解析异常。

## gorm {#gorm}

### 1️⃣ 表名问题

`Create()` 时：

- struct 名默认映射为 **复数表名**

示例：

| Go Struct   | MySQL 表      |
| ----------- | ------------- |
| BannerModel | banner_models |
| Banner      | banners       |

如需自定义：

```go
func (BannerModel) TableName() string {
    return "my_banner_table"
}
```

------

### 2️⃣ 通用 Model

```go
type MODEL struct {
	ID         uint      `gorm:"primaryKey" json:"id"`
	CreateTime time.Time `gorm:"default:CURRENT_TIMESTAMP" json:"create_time"`
	UpdateTime time.Time `gorm:"default:CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP" json:"update_time"`
}
```

------

### 3️⃣ MySQL 编码问题

建表必须：

```sql
ENGINE=INNODB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci;
```

否则未来一定乱码。

------

### 4️⃣ 插入必须使用 &

错误示例：

```go
global.DB.Create(model.MessageModel{})
```

正确：

```go
err := global.DB.Create(&model.MessageModel{
	SendUserID: pm.SendUserID,
	RevUserID:  pm.RevUserID,
	Content:    pm.Content,
}).Error
```

否则会出现：

- 空时间
- 空指针
- 无法插入

------

### 5️⃣ 更新 map 类型

如果参数是：

```go
map[string]any
```

不要重新定义：

```go
map[string]interface{}
```

否则要断言，很麻烦。

## go-mysql-elasticsearch {#go-mysql-elasticsearch}

功能：

MySQL 与 Elasticsearch 数据同步。

环境：

- Windows 11
- ES 7.12.0（Docker + WSL）

------

### 构建

```bash
make
```

或：

```bash
go build -o bin/go-mysql-elasticsearch.exe ./cmd/go-mysql-elasticsearch
```

------

### 启动 ES

```bash
docker run -p 9200:9200 -p 9300:9300 \
--name go-mysql-es \
--privileged=true \
-e "discovery.type=single-node" \
-d elasticsearch:7.12.0
```

------

### 三件套必须配套

- go-mysql-elasticsearch.exe
- go_mysql_river.toml
- es-data 目录

启动：

```bash
./bin/go-mysql-elasticsearch.exe -config="./go_mysql_river.toml"
```

### 时间字段踩坑

方案一：

ES 用 long 存时间戳。

方案二：

```json
"create_time": {
  "type": "date",
  "format": "yyyy-MM-dd HH:mm:ss||epoch_millis"
}
```

Go 必须格式化：

```go
time.Now().Format("2006-01-02 15:04:05")
```

否则报错。

## golang-migrate {#golang-migrate}

### 命令行迁移

```bash
migrate create -ext sql -dir migration create_table_to_t
```

执行：

```bash
migrate -path migration -database "mysql://root:123456@tcp(127.0.0.1:3306)/t" up
```

Dirty 错误：

```bash
migrate force 版本号
```

------

### 程序迁移

导入：

```go
_ "github.com/go-sql-driver/mysql"
"github.com/golang-migrate/migrate/v4"
"github.com/golang-migrate/migrate/v4/database/mysql"
_ "github.com/golang-migrate/migrate/v4/source/file"
```

核心代码：

```go
m, err := migrate.NewWithDatabaseInstance(
	"file://migration",
	"t",
	driver,
)
err = m.Up()
```
